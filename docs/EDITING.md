# Demo video editing

Produce a finished demo from real product evidence, narration, and a script. The engine is
config-driven so one pipeline can render a dramatic Save-the-Cat product story, a short before/after
promo, a causal investor film, or a chaptered sales walkthrough. A production contract protects
truth, continuity, authority, audio, and artifact identity before an AI judge is allowed to comment
on taste.

Read [PRODUCTION_CONTRACT.md](./PRODUCTION_CONTRACT.md) before authoring a final-delivery project.

## Pick the grammar before the cut

- **Save the Cat** is for a dramatic product story. Compress all fifteen ordered beats into the
  available runtime, group inseparable beats inside real shots, and mirror the opening in the final
  image. The customer or maker remains the hero; the product makes transformation possible.
- **Causal workflow** is the default for a real product demo. Follow one case or unit of work from
  input through evidence, action, result, learning, and outcome.
- **Before/after** is for a short transformation promo. It may use a flash pivot, score, captions,
  music, and abstract iteration—but only when those elements are truthful.
- **Walkthrough** is for a longer buyer or training tour. Every chapter still needs an input,
  action, and result.

The delivery profile is separate from story grammar. Use `yc_60`, `yc_3m`, `investor`, or `sales`
and then set the owner-approved hard runtime in `production`. Do not force a three-minute investor
story into a short-social pacing rubric.

## Pipeline

1. **Contract and script** — a JSON shot list (`script.json`) plus a `production` block. The
   canonical short-promo schema is
   the contract generated by `pdd new`; each shot is one of `title | clip | split | stat | cta | score | bars | strip`:
   ```json
   {
     "fps": 30,
     "music": "mood prompt for music.py",
     "brand": { "name": "Product Demo ", "accent": "Director" },
     "shots": [
       { "n": 1, "kind": "title", "title": "...", "durSec": 2.5, "vo": "..." },
       { "n": 2, "kind": "clip", "src": "raw.mp4", "inSec": 3, "chapter": "BEFORE", "vo": "..." },
       { "n": 3, "kind": "clip", "src": "polished.mp4", "chapter": "AFTER", "flash": true, "vo": "..." }
     ]
   }
   ```
   When a shot has `vo`, the on-screen caption defaults to that exact line. Captions are optional;
   set `caption: false` when they would obscure a dense live-product surface. Author narration from
   real footage and verified positioning.
2. **Preflight** — run deterministic source, story, authority, claim, camera, and audio checks:
   ```sh
   python tools/preflight.py --project projects/my-demo --profile yc_3m --strict
   ```
3. **Voiceover** — `vo.py` can create ElevenLabs `eleven_v3` or Gemini TTS as one file per shot.
   In that mode, keep clean subtitle text in `vo` and put ElevenLabs performance tags in `vo_tts`.
   For a single continuous performance, remove every per-shot `vo`/`vo_tts` and put tagged speech in
   `narration.text`; the tool writes and manifests the declared narration file. Use the per-script
   `pronounce` map to swap brand spellings to phonetics for the TTS only (e.g. "ACME" ->
   "Ack-me") while the caption keeps the real spelling. Narration-locked investor films should
   instead declare one hashed global supplied `narration` master and an exact `narrationMap`.
   For a generated announcement master, set `narration.fromMap=true`, put one complete thought and
   `shotN` in every map entry, and use ElevenLabs character alignment.
4. **Pace narration** — run `pace.py --write` after voice and before music. It moves subject-changing
   cuts to frame-safe gaps between complete thoughts and fails when the read cannot fit with its
   protected tail. Never cut picture at arbitrary round seconds during active speech.
5. **Music** — `music.py`: ElevenLabs Music or Lyria, a continuous instrumental bed
   sized to the narrated runtime. Set the mood with the script's `music` prompt. The engine mixes
   it low under the voice. Music is optional and should not make a live-product demo feel like an ad.
6. **Assemble** — `build.py` maps the script to Remotion props (`Timeline.tsx`): clips with
   in-points, kinetic lower-third captions, chapter pills, title/stat/cta cards,
   per-shot or global audio, SFX, and optional before→after treatment. Render to MP4. The build also
   writes `build-plan.json` and `artifact.json`, binding source hashes and exact frame boundaries to
   the output.
   For an agent-operated product, `workbench.py` can turn a committed, whitelisted session JSON into
   reproducible footage that keeps the prompt, tool action, changed files, live preview, render, and
   QA state visible together. Label it as a curated replay; never present it as a literal recording
   of a proprietary Claude or Codex interface.
7. **Deterministic final QA** — prove that the exact artifact decodes and matches its contract:
   ```sh
   python tools/qa.py --video projects/my-demo/out/demo.mp4 \
     --project projects/my-demo --require-artifact --strict
   ```
8. **Judge** — only after QA passes, have Gemini watch and hear the exact bound artifact at `fps=4`
   (raise toward the API max
   of 24 for fast-cut pieces). Returns strict JSON scores; an improve loop acts on the weaknesses:
   ```json
   {
     "overall": 0,
     "scores": { "hook_1s": 0, "narrative_tension": 0, "tempo_rhythm": 0, "show_dont_tell": 0,
       "motion_design": 0, "vo_performance": 0, "sound_design": 0, "clarity_one_thing": 0,
       "proof_credibility": 0, "polish": 0, "wow_moment": 0 },
     "biggest_weaknesses": ["ranked, with mm:ss"],
     "specific_upgrades": [{ "area": "hook|motion|vo|...", "change": "concrete fix" }],
     "would_forward": false,
     "one_line_verdict": "the unvarnished truth"
   }
   ```
   Treat the result as advisory. Use a pinned model, median of three runs, and pairwise comparison in
   both display orders. A model score never waives a deterministic failure.

## Craft rules (each one was a real mistake first)

- **One dramatic or causal story, not a feature tour.** Each beat must change the situation for the
  next one. In Save the Cat, the product promise belongs in `fun-and-games`; pressure and a real
  setback must still force a new plan before the finale.
  input → evidence → hypothesis → test → result → bounded decision → durable outcome. If the
  narration can be reordered without consequence, it is a list rather than a story.
- **Progress is visible.** Reasoning, recommendations, and queue results appear after their initiating
  events. A finished answer visible from the first frame reads as a preset presentation.
- **Authority is part of the product.** Let the agent own reversible, low-friction work. Show the
  accountable human only where the decision is consequential. Restraint under uncertainty is a
  credibility beat, not a weakness to edit around.
- **Escalate with a test, not another feature.** When one signal is inconclusive, let the agent say
  what evidence would change the decision, run the lowest-friction falsifiable check, and update the
  case from the result. That creates real stakes while showing judgment; an extra dashboard or a
  drafted email usually does not.
- **Counters are not casework.** At scale, show events, evidence, a receipt, or at least one completed
  packet. Rows moving quickly can demonstrate energy while proving nothing.
- **Captions are optional; subtitles are exact.** When a caption functions as a subtitle, it must
  match the spoken words. A sparse actor/session label may identify real context. Suppress captions
  when they cover the product or duplicate a global human narration without helping comprehension.
- **One spoken action per visible step.** Read narration aloud and use the words an operator would
  actually say. Avoid machine-translated status prose, long inventories of capabilities, and API-like
  verbalizations. When a recorded human master is approved, its actual performance—not an older
  written draft—is the timing and wording source of truth.
- **Pace by content, not a universal stopwatch.** Before-montage clips may be fast; a consequential
  decision may need a deliberate hold. Remove time that carries neither speech nor meaningful state
  change, but protect setup required to understand who, what, and why.
- **Redact identifiers, never the value.** Keep the work that proves the story sharp and
  legible (plans, public records, the product surface); hide only client identifiers. Full-
  frame blur destroys the point and looks like a mistake — use it only on an identifier-dense,
  low-value clip (a cluttered tracker). Everywhere else: blur just the top browser-chrome
  strip (tabs/URL/filenames) and box specific marks (a title block, a logo).
- **Solid "redacted", not blur, for labeled fields.** A vision model confabulates a plausible
  value from a blurred field next to a label like "address" — it invents a different fake
  address every run. Replace the text with the literal word "redacted" so there is nothing to
  fill in. Always verify the actual frame; treat a judge's "address leak" on a redacted field
  as a likely false positive.
- **Live web capture: redact at the source.** Inject a MutationObserver that rewrites any text
  node matching a token list + patterns (street suffixes, LLC / P.C. / Trust / Architect,
  block/lot `\d+/\d+`, filenames) to "redacted", re-applied on scroll / stage / navigation. A
  PDF rendered to `<canvas>` is not DOM text — zoom past the title block or box it.
- **Show the work.** Open from the real entry point (upload the file), and feature one
  click-to-evidence beat (click a fact, the cited source opens with the value highlighted). This prevents the "magic wand" failure mode where a viewer assumes the system outputs results without ingestion or verifiable lineage.
- **Be honest about the actual boundary.** Do not imply autonomy the product lacks, but do not add
  unnecessary human review either. Use only verified numbers. Do not imply a customer used a model
  they never had. This prevents both the "phantom capability" failure and the opposite failure where
  a real autonomous workflow is made to look like presentation software operated by a reviewer.
- **Slides explain context, never product behavior.** A sourced traction fact or market statement may
  need a clean slide. An agent action, state transition, queue result, or receipt must remain live
  product evidence.
- **Integrations must look inhabited.** A handoff to Slack, email, or a case system should land in the
  customer's actual workflow: a specific operational channel, a recognizable sender, a useful
  completed-work summary, exceptions, and a path to evidence. A generic internal `#product` channel
  or unexplained codename makes a real integration look mocked.
- **Introduce labels in story order.** Do not name an internal agent, teammate, or customer on screen
  before the viewer knows who it is. A brief freeze-frame introduction can work after the person's
  first complete sentence; return to the original moving frame afterward.
- **End once.** After the operational climax, use only necessary proof, a fresh forward-looking state,
  and one CTA. Replaying setup or old product screens creates a second opening after the story ended.

## Causal live-product structure

This is a reusable spine, not a mandatory shot count:

1. A real person or product state establishes the operating problem.
2. The product accepts the actual input and loads the context it needs.
3. One hero case exposes a contradiction or uncertainty.
4. The agent states and visibly launches a falsifiable test.
5. The result appears progressively; the product refuses an unsupported conclusion.
6. One accountable human action resolves the consequential boundary.
7. A receipt binds evidence, policy, actor, and outcome.
8. The exact correction becomes reusable knowledge with source-case provenance, then is safely
   replayed against frozen history before touching live traffic.
9. Scale is shown with event- or packet-backed execution, not only a counter.
10. The result arrives in the customer's real working system with completed work, exceptions, and
    evidence—not a generic “done” notification.
11. Any traction or market context is sourced and visually separated from product proof.
12. A fresh product state carries the story forward; one CTA closes it.

Give the unique differentiation more screen time than commodity navigation. Browsing, form filling,
and a queue animation are setup unless they directly prove the product's distinctive mechanism.

## Before/after short-promo structure

- **0:00 - 0:03 Cold Open**: Pain point (3s raw file/quote, e.g., "This auditing takes days.").
- **0:03 - 0:15 Manual Montage**: 4-5 fast cuts (2.5s each) of manual UI dragging/scrolling, set to upbeat music.
- **0:15 Transition Beat**: Title card (1.5s) naming the real bottleneck ("Trusting every number").
- **0:16 - 0:45 Product Demo**: Direct cut to product executing the workflow, VO explaining the engine, highlighting live source citations (show-the-work beat).
- **0:45 - 0:50 CTA**: Static/fade slide with company URL and contact email.

## Acceptance

Acceptance has an order:

1. `tools/preflight.py --strict` passes the source and production contract.
2. `tools/build.py --contracts strict` produces the intended exact-frame artifact.
3. `tools/qa.py --require-artifact --strict` passes decode, hash, timing, audio, black/silence, and
   proof-sheet generation.
4. A human inspects every cut boundary, every declared critical range, and all redaction-sensitive
   frames.
5. The AI judge is then used for narrative, comprehension, pacing, and comparative taste.

Always: zero verified redaction leaks, no unsupported claims, the declared human/agent boundary,
one coherent ending, and captions matching speech wherever subtitles are used.

## Production learnings (added 2026-06)

More rules earned cutting real investor demos with this engine. Several refine the ones above.

- **Use stills for explanation and live takes for causality.** A clean still can clarify a sourced
  number, static artifact, or non-interactive context. It cannot prove that an agent initiated work,
  reasoning arrived, a decision changed state, or a queue completed. Those beats require one
  continuous live take. When a still is appropriate, bake the exact frame and use a restrained
  push-in. This also dodges a nasty failure
  mode: if your source recording lives in `/tmp` it can get cleared between runs, and a re-bake
  then silently reuses a stale frame — re-copy the source and eyeball the bake's first frame.
- **Connected focus, not jumpy crop resets.** On one product screen, use one clip and connected
  camera regions. Pan at a stable scale between nearby targets; do not cut to a differently cropped
  copy of the same state or zoom out and back in. Capture at high resolution so the focused text
  remains crisp.
- **Frame the target, context, and cursor together.** A crop that enlarges the narrated row but
  removes its status, safeguard, or action is a regression. Keep the cursor inside the declared safe
  margin through the entire camera transition, not only at the click frame.
- **Preserve people by default.** Moving footage of a customer, founder, or teammate retains its
  source framing unless the brief explicitly authorizes a punch-in. A freeze-frame title treatment
  may be authored without turning the live conversation into alternating close-ups.
- **Frame the identifier out; don't draw a box over it.** A grey redaction box reads as a smudge
  on screen and the judge flags it. Prefer cropping the identifier out of frame. For an
  internal/investor cut where the real customer is shown *as proof*, show it plainly. Box only
  as a last resort, and verify by eye. (Supersedes "box specific marks" above for on-screen video.)
- **No meta-commentary on screen.** Strip anything that narrates how the cut/doc was made —
  "companion: before/after demo", "emails omitted", "pending confirmation", internal status,
  "(estimated)" scaffolding. The viewer must never see the wiring. This is the single most
  common leak in an otherwise-clean cut; do a dedicated read-through for it.
- **Two voices tell two roles.** A warm, weary voice for the customer's pain (the BEFORE
  quotes); a calm, trustworthy narrator for the product (the AFTER). Audition candidates and
  let an ear/the judge pick — a "weary expert" read scored 92 vs 80 across two voices. Set a
  per-shot `voice` or a `voices.before` / `voices.default` convention.
- **No AI-tells in the VO.** No rule-of-three triads, no "in today's world", no
  seamless/robust/leverage/unlock/elevate, no em-dashes, no hype. Plain, specific, declarative.
  Spell numbers as said ("just under one point four million").
- **Bespoke, model-judged sound beats stock.** Generate the palette and let a model *listen*
  and keep the best of N per cue (`tools/sfx.py`), then map sound to meaning with per-beat
  `accent`: a click on a click, a soft `data_tick` while scanning, a `success_chime` exactly on
  the win, a `confirm_cash` on the money number, a `pivot_boom` + `riser` at the pivot. Music
  sits low (~0.10) under the VO; payoff stingers ride ~0.6–0.8 so they punch through.
- **A steady music bed beats a clever one.** An "arcing" tense→warm score consistently scored
  *lower* than a clean steady instrumental. Don't out-think the music.

## Scripting for attention (added 2026-06, rebuilding the promo)

Wiring two frameworks into the script moved a flat before/after into a real 13s piece.

- **Lead with the customer's sharpest *pain*, not the feature** (Value Proposition Design). For
  a demo tool the extreme, unaddressed pain isn't "editing is slow" (any editor fixes that) —
  it's *"I can't trust an AI editor to produce something I'd publish; there's no quality bar."*
  Anchor the whole cut on the one differentiator that pain implies (here: **a separate model
  grades the cut and re-cuts until it passes** — "the demo that grades itself").
- **Open on a *change*, and pose a question** (Storr, *Science of Storytelling*). The first
  second must register change, not a label — so the "directed" side **wipes in** next to the raw
  one (engine: `split` animates the right pane via `clipPath`). And an *interrogative* hook beats
  a statement: "Which one would you actually finish?" out-scored "You only finish one of these"
  by ~20 pts on `hook_1s` across runs (curiosity gap = Loewenstein's lever #1). The hook can
  carry the pain *as a question*.
- **"Because", not "and then."** Chain the beats causally: point Claude at the clip → *so* it
  directs the cut → *then* a different model grades it → *because* it failed it re-cut → *so* now
  it's yours. Momentum reads as a chase; "and then… and then" reads as a slideshow.
- **Make the proof concrete and the meta-twist land.** A number is your best concrete detail —
  animate it (`score` kind: a count-up 0→N with a filling bar and a ✓). The surprise (Storr's
  "violation of expectations") is that the AI is *harsh on itself*; the self-reference should be
  about the **judge** ("…and it graded this very video"), since grading is the differentiator.
- **New beat kinds for data-driven payoffs.** `score` (count-up + bar + tick), `bars` (rejected
  takes climbing past a PASS line until one clears it — an abstract "it re-cut until it passed"
  visual that reuses no footage), `strip` (a filmstrip of prior shots panning). The `bars` beat
  replaced a literal montage that the judge read as "every screen shown again" — when you only
  have two source screens, *abstract* the iterative process instead of replaying it.

## The judge loop (run it like an experiment)

- **Bind the artifact before judging.** Require `artifact.json`; a similarly named or stale MP4 is
  not the candidate. The judge report must carry the exact hash and build ID.
- **Pin one judge model when comparing cuts.** Different models (and "-latest" aliases) disagree
  by 3–5 points; a "regression" is often just a model swap. Fix `--model` and ignore ±2.
- **The judge is noisy — judge the *same* render 2–3× and read the median.** The render is
  deterministic; the judge is not. The same fixed cut drew 72, then 45/47 on re-runs. Don't act
  on a single draw, and don't chase one run's component scores (they swing ±20–50). Re-judge,
  take the median, and weight the *consistent* complaints (dead air, length) over the volatile ones.
- **Continuity is not repetition.** In a live-product profile, remaining on one screen while state,
  evidence, or story function advances is usually stronger proof. Penalize replayed conclusions and
  repeated states with no new information—not a source filename.
- **Read both `overall` and `overall_model` in context.** `overall_model` preserves the raw model
  response; `overall` adds profile-aware structural calibration. Neither supersedes deterministic QA
  or an explicit owner-approved contract.
- **A self-promo with only two source screens has a ceiling (~`overall_model` 55–72).** The
  rubric reserves 85+ for zero-repetition, and two visuals can't get there no matter how tight.
  Don't grind for 90 you can't structurally reach — capture more varied footage instead.
- **Dead air after the VO is the most consistent real complaint.** Tighten each beat to end as
  the line ends (`build.py` pads VO by only +0.2s); keep card holds short and add late motion (a
  `PASSED` stamp, a continued count) so a held beat still moves.
- **Verify fixes, don't trust them.** Apply the judge's `specific_upgrades`, re-render, re-judge,
  and keep only what raises the *integrated* cut — some "improvements" (a louder mix, an arcing
  score) lower it. Pair with [auto-improve](https://github.com/crimeacs/auto-improve) as the gate.
- **Use order-reversed pairwise comparison.** Compare champion/candidate and candidate/champion.
  Ship a candidate only when it wins both orders after passing deterministic gates. A split is a
  rejection, not an invitation to rationalize the score.
- **Recognize a cut-mechanics plateau.** After three plausible in-point, zoom, or pacing candidates
  fail to beat the champion, stop recutting. The recurring complaint likely needs a new narration
  line, product state, live capture, or story beat.
- **Eyeball the generated QA evidence.** The judge misses what every-five-second, cut-boundary, and
  full-frame critical-range sheets catch—a clipped caption, cropped cursor, incomplete error page,
  or accidental black frame.
- **Acceptance:** for a self-promo, `would_keep_watching = true` and a stable (median-of-3)
  `overall_model` at the structural ceiling. For an investor cut with rich, varied footage, hold
  the higher creative bar only after deterministic acceptance. Always: zero verified redaction
  leaks, zero meta-commentary on screen, and subtitles matching narration when present.

## Delivery

- Keep the deck/demo **online** when you want engagement analytics; only attach a file when the
  recipient needs it offline. When uploading to a drive via a CLI, run it from the project root
  (some tools refuse files "outside the current directory" and print a banner line you must strip
  before parsing JSON), and **never set external share permissions on someone's behalf** — leave
  that one step to the owner.
